# SamAPI

SamAPI 是一个本地模型路由控制台，用于管理上游模型供应商、下游调用密钥、Header 模版和模型路由。第一阶段实现切换型路由：固定选择一个供应商地址、模型、Header 模版和 endpoint，然后通过本地 `localhost` 代理给不同客户端调用。

## 启动

```bash
pnpm install
pnpm dev
```

默认地址：

- 管理台：`http://127.0.0.1:5173`
- 开发 API：`http://127.0.0.1:8788`；生产运行 `pnpm start` 默认使用 `8787`
- 数据库：`data/samapi.sqlite`（自动迁移旧 JSON 数据）

指定数据目录：

```bash
SAMAPI_DATA_DIR=/path/to/data pnpm dev:api
```

## 客户端调用

```bash
curl http://127.0.0.1:8787/proxy \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-samapi-..." \
  -d '{"model":"default-messages","messages":[{"role":"user","content":"hello"}]}'
```

当系统没有创建任何密钥时，代理接口允许本地开发调用；创建密钥后，请使用 `Authorization: Bearer <key>` 或 `X-API-Key: <key>`。

### 系统设置

「系统设置」首页只展示各项入口和当前配置摘要。下游模型映射、错误码重试、请求超时、日志保留、界面主题、数据备份、管理员密码和会话有效期均在独立的二级弹窗中操作。表单只保存当前设置项，保存成功后返回设置首页；取消或关闭不会保存未提交的修改，保存失败则保留表单以便重试。主题选择后自动保存，备份导入仍需确认覆盖。

「上游错误码重试配置」支持为重试设置时间规则：立即重试、固定间隔，或在自定义最短 / 最长时间内随机等待。时间以秒为单位，范围为 0–3600 秒，支持最多 3 位小数；随机间隔会在每次重试前独立抽取。时间规则统一用于已配置且重试次数大于 0 的错误码，不延迟首次请求或重试耗尽后的目标切换；等待期间客户端取消会立即停止。未配置此项的旧数据及备份继续使用原有的随机 1–3 秒，保存与备份恢复均保留时间规则。

### 按客户端或项目选择模型

在「系统设置 → 下游模型映射」添加规则，填写下游请求的模型名和匹配条件，再依次选择供应商、该供应商的可用模型和可选的请求头模版，无需预先创建路由。模型列表来自「模型管理」，合并已启用上游密钥的模型并去重；切换供应商会清空模型选择。CLI 和 App 可以共用客户端 Key、都请求 `gpt-5.6-sol`，再由不同规则选择各自的上游模型及上游请求头。直接映射沿用客户端请求协议（通用 `/proxy` 入口默认 Chat Completions），官方账号仍使用已有的协议转换和账号选择逻辑。已有的路由映射继续保留原路由的模型、协议和请求头配置，重新选择供应商或模型后才改为直接映射。

- 客户端条件可匹配原始 `originator`、`User-Agent`、`X-App` 或自定义请求头，支持完全相同、包含和前缀匹配，请求头名称及值均不区分大小写。例如 App 可用 `originator` 完全相同于 `Codex Desktop`，CLI 的值以实际请求日志为准。
- 项目目录条件依次读取 `X-Samapi-Project-Path`、旧版 `X-Samapi-Project`、`x-codex-turn-metadata` JSON 中 `workspaces` 的工作区目录，优先使用第一个非空来源。支持路径完全相同、包含、目录及子目录，路径区分大小写；目录前缀不会误匹配同名前缀的兄弟目录。没有项目标识、元数据格式无效时，不命中项目条件。不会从聊天内容猜测项目，也不会沿用其他请求的项目。
- 项目名称条件读取 `X-Samapi-Project-Name`，支持完全相同、包含和前缀匹配，不区分大小写；可与项目目录条件组合。名称不会被当成目录使用。这两个新请求头支持 `encodeURIComponent` 编码，中文路径、中文名称和字面量 `%` 请编码后发送，规则中填写解码后的值。
- `X-Samapi-Project-Path`、`X-Samapi-Project-Name` 和旧版 `X-Samapi-Project` 仅用于 SamAPI 本地路由和下游请求日志；无论来自下游透传还是请求头模板，转发上游前均会移除。其他客户端元数据（包括原有 `x-codex-turn-metadata`）保持不变。
- 新规则默认没有附加条件，仅按下游模型名匹配；点击「添加条件」后才限制客户端或项目，已添加的条件须全部满足，也可以全部删除。规则自上而下匹配，仅使用第一条命中的规则。可以将「某项目 + Codex Desktop」放在前面，无条件规则放在后面作为该模型的默认映射；未命中任何规则时继续按原模型名查找路由。命中规则的供应商、模型或旧目标路由不可用时会明确报错，不会转到其他供应商。
- 点击「保存设置」后对后续请求生效，规则随配置备份导出和恢复。客户端 Key 的模型权限按下游原始模型名检查；日志与消费统计使用实际上游模型。模型列表会为携带相应客户端 / 项目标识的请求返回可用映射名，查询模型列表时也应携带相同标识。

客户端应在每次模型请求、工具回传及模型列表查询中发送当前项目的绝对路径和名称。Codex 已携带的工作区元数据会自动补齐这两个字段；无法取得项目上下文的请求仍会正常转发，只是不命中项目限定的映射规则。示例：

```http
X-Samapi-Project-Path: /Users/you/dev/samapi
X-Samapi-Project-Name: samapi
```

两个项目即使都请求 `gpt-5.6-sol`，也可按不同路径或名称映射到不同供应商的模型。项目路径必须由调用方的客户端配置或请求代码提供；SamAPI 不包含客户端实现，不能自动取得远程客户端的本地目录，也不会使用 SamAPI 服务自身的运行目录代替。请在客户端向 SamAPI 发请求时添加这两个字段，不要在 SamAPI 的上游请求头模板里配置。实际收到或从 Codex 元数据补齐的字段可在「请求日志」展开请求头确认。

在设置中为 `599` 配置大于 0 的重试次数后，上游的推理、正文和工具调用等完整数据帧会立即交付给客户端，不再等待整次响应结束。若随后收到错误事件或发生断流，网关会拦截该错误、在同一个下游连接内重试，并继续追加新尝试返回的数据；重试产生的 keepalive、`response.created` 等前置信号不会重复发送。错误发生前已经交付的内容无法撤回，因此客户端可能看到多次尝试的部分内容。配置 `100` 表示首次尝试加最多 100 次重试；客户端取消时立即停止。

## 文档

请求日志按一次用户输入归并，列表和详情只显示当次输入；同一轮里的多次接口调用、上游重试/切换、工具调用和工具回传在同一条日志内查看。用户输入按内容去重，只存一份正文；下游请求头只保留该轮首个请求的一份（密钥和 Cookie 脱敏），各次调用分别保留上游目标和结果。已有日志会自动移除重复请求头。系统提示、助手历史、工具定义和上游请求体不保存，图片、音频、文件的二进制内容以提示文字代替。

模型列表查询和供应商模型发现单独标记为「获取模型」，不作为用户输入，也不会因复用会话头而并入对话日志。本地模型列表会注明无需请求上游；能够明确识别的已有记录会自动补充标记，保留原日志 ID、时间和返回结果。

详情单独展示最终结果及对应上游，处理中显示会自动更新的「当前结果」；请求头和完整调用过程默认折叠，按需展开查看每次接口、重试及工具回传。新内容追加时，详情及正文滚动区距底部不超过 80 像素才自动跟随；向上查看或展开历史内容时保留阅读位置。独立结果区优先读取主会话的最后一次接口结果，没有主会话标识时读取最后一次接口结果，不额外复制存储正文。

Codex 的 `root_turn_id` / `turn_id` 会自动用于关联。其他客户端可以发送同一轮固定的 `X-Samapi-Turn-Id` 和会话级 `X-Samapi-Session-Id`；没有轮次标识时，网关通过工具调用 ID、工具回传及 `previous_response_id` 关联已知请求。关联按客户端 Key 隔离，不会只因消息文字相同就合并两次输入。历史日志只在包含明确会话、轮次标识时归并，无法补回之前未保存的工具结果。

流式返回会持续更新同一条日志，工具发出后显示「等待工具回传」，新的接口请求进入后恢复「进行中」；列表及已打开详情默认每 2 秒刷新。工具在客户端本地执行的过程不经过网关，只能记录上游下发的调用及客户端随后带回的结果。「已返回」表示已观察到的接口均已返回且没有待回传工具，后续同轮请求仍会更新此日志。

每次上游结果和工具回传默认最多保留 20,000 字符，可通过 `SAMAPI_LOG_BODY_MAX_CHARS` 调整。保留数量按整条用户输入日志计算，仍在处理接口请求的日志暂不裁剪；删除/清空会一起删除该轮所有调用，但不会清除独立消费账目。启动时会精简旧 SQLite 日志并回收数据库空间；旧日志之前已经截断的正文无法还原。服务重启前未结束的接口标记为中断，保留已收到的部分结果。

## 消费统计

在「消费统计」按客户端 Key、日期查看输入、缓存命中、缓存写入、输出及总 Token，并按客户端、模型和日期汇总。统计从功能启用后的请求开始，每次上游重试独立计入，同一客户端请求仍能关联。流式与非流式响应优先使用上游实际 `usage`；缺失时，按实际发送的完整上下文（含系统提示、历史与工具定义）及收到的正文、推理、工具参数估算。文本使用本地 BPE 分词器：较早的 GPT-3.5/GPT-4 使用 `cl100k_base`，现代 GPT 使用 `o200k_base`；其他供应商使用后者作近似参考，消息结构和不可见内容仍需上游实报。不保存额外请求正文，不把协议中的加密内容或 Base64 当作 Token；工具结果和工具定义中普通的 `data` 字段会正常计入。部分实报计数会保留，后续完整实报可覆盖估算，估算不会覆盖实报。

页面分别展示实报、估算、处理中及缺少估算依据的次数，总 Token 和消费包含估算并单独标出。缓存未上报时，参考同客户端、同供应商、同模型及缓存模式、24 小时内、相近输入长度的至少 3 次实报，按缓存比例的中位数估算，并记录样本数；没有足够依据的金额保留未定价。未观察到生成内容的失败请求按 0 估算，图片、音频及不可见推理无法完整计入，因此金额不代表供应商账单或 Codex Credits 扣减。「补算当前范围的历史未知用量」优先参考同次请求、同供应商的实报输入和缓存比例，再使用同客户端、同供应商、同模型附近最多 20 次实报的中位数；历史输出优先使用保留的回复，否则使用历史参考值。历史补算标记为估算，不使用估算记录继续推算其他记录；没有参考数据的记录保留未知。

「模型定价」每天北京时间 **08:00** 自动请求 OpenAI、Claude、Gemini、DeepSeek、Grok、GLM、MiniMax、Qwen、Kimi、MiMo 和 StepFun 的官方公开价目数据，使用 USD / 百万 Token；Qwen、MiMo、StepFun 使用国际站美元价格。首次启动或错过更新时自动补查，失败后每小时重试并保留上次价格。任务由 SamAPI 后台执行，关闭网页不影响更新，服务停止期间的更新会在下次启动时补查。页面可查看来源、更新时间、计费规则与失败原因，也可立即更新。

缓存命中、OpenAI `cache_write_tokens`、5 分钟和 1 小时缓存写入、普通输入与输出分别计费，并按官方说明处理长上下文阶梯、分时价格和优惠到期时间。账目保存实际响应的 `service_tier`，响应缺失时参考实际转发的请求档位；OpenAI 同步 Standard、Flex、Fast/Priority，MiniMax 同步 Standard、Priority，各档位保留独立的长上下文规则。无法确认价格的档位（如尚无公开价格的 Ultrafast）保留未定价。Qwen 区分显式与隐式缓存；缺少缓存模式的历史记录不猜测缓存优惠。无法确认的模型名称、计费模式或缓存单价保留为未定价。工具调用、缓存存储、图像与音视频等额外费用不计入 Token 估算。

手动配置支持供应商专属价和通用价，优先于自动价格且不会被每日更新覆盖；手动价格按填写的统一单价计算。已计费记录保留调用时的价格与规则，未定价用量可在页面按当前价格补计。未定价不等于免费，页面单独显示其数量。消费账目和价格独立于日志与配置备份，清空日志、删除客户端 Key 或恢复配置不会重置账目；完整迁移请复制 SQLite 数据库。

## 账号管理

「账号管理」集中管理 GPT、Grok、Claude、DeepSeek 和 Gemini 的多个账号。Grok 与 GPT 并排显示，原「临时账号」入口已合并；现有账号、OAuth 授权、导入数据与路由直接保留，无需重新导入或登录。

- GPT 支持登录 ChatGPT、导入 CPA / Sub2API / auth.json / ZIP，以及添加 OpenAI API Key。登录后自动检查额度；检查时可刷新失效的 OAuth 授权，已有重置卡操作仍可使用。
- Grok 支持导入 CPA / grok2api 单账号 OAuth JSON 或 ZIP，导入后自动检查。凭据刷新、可用状态、额度、启停和批量操作均在账号管理中完成，模型继续在「模型管理」维护。
- Claude、DeepSeek、Gemini 使用官方 API Key 接入，检查时按供应商协议验证认证并同步可用模型。网页订阅账号与开放平台 API Key 是不同凭据。
- 可为每个供应商设置顺序优先、轮询或随机策略，启停、重命名、更换 API Key、批量检查与删除账号。账号不可用时尝试同供应商的其他可用账号。模型范围与启停状态参与实际路由选择。
- 在「模型路由」为客户端配置账号池，支持切换型与分组型路由。账号列表不返回访问令牌、刷新令牌或私钥，账号凭据仅在服务端存储。
